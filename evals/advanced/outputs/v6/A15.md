**The deployed SDK 2.3.1 and server protocol 2.4 govern these requests.** Client `timeoutMs` values are milliseconds. With `legacyMode=false`, `timeout` is ignored, without conversion or aliasing. Resolution takes the first non-nullish `timeoutMs` from call options, then constructor; otherwise it converts the environment value with JavaScript `Number`, defaulting to `1500` if absent. [A15-MIGRATION; A15-IMPLEMENTATION]

| Request | Client wait timer | `x-deadline-ms` header | Server computation budget |
| --- | ---: | ---: | ---: |
| R1 | 6000 ms | `6000` | 5000 ms |
| R2 | 2500 ms | `2500` | 2500 ms |
| R3 | Rejected before network request | None sent | No request reaches server |

R1's call-level `timeoutMs:6000` overrides constructor `2500` and environment `4000`. R2's call-level `timeout:1` is ignored, so constructor `timeoutMs:2500` wins. R3 has no applicable `timeoutMs`; `Number("2s")` produces `NaN`, which fails validation. Its legacy constructor `timeout:30` does not rescue it. These follow from [A15-REQUESTS; A15-MIGRATION; A15-IMPLEMENTATION].

The server budget is `min(header, 5000)` milliseconds. Its absent-header default of 1000 ms is irrelevant to R3 because no request is sent. [A15-SERVER]

**R1's 5030 ms trace is consistent with the limits.** The response arrives before the 6000 ms client timer expires. The server's 5000 ms cap measures computation from its own start; transit and response delivery add wall time. A 5000 ms computation budget plus 30 ms outside computation is compatible with this trace, although its detailed timing breakdown is unavailable. [A15-REQUESTS; A15-SERVER]

The SDK 1.8 guide's seconds and 30-second default apply to 1.x. The newer website's duration-string parser and 2000 ms default apply to 3.x. Neither governs this deployment. [A15-OLD; A15-LATEST]

For a two-second budget, set **call option `{timeoutMs:2000}`**. This overrides existing constructor/environment values, sets the client timer and transmitted header to 2000 ms, and gives the server a 2000 ms computation budget. Network time still means a server deadline response is not guaranteed to arrive before the client timer. [A15-IMPLEMENTATION; A15-SERVER]
