No. **JWT is a format for a token; OAuth is a framework for giving an application permission to access a service.** They can be used together.

- **JWT (JSON Web Token)** packages statements such as a user identifier, permissions, or an expiry time into a string. A signed JWT lets a recipient check that the contents were signed with a trusted key and have not been changed. The format itself does not specify how an application obtains permission.
- **OAuth 2.0** defines how an application obtains and uses an **access token**: a credential it presents when requesting access to a service. That token can be a JWT, but it can also be a string whose meaning the service looks up.

For example, you might allow a photo-printing app to read photos from your storage account without giving it your password. OAuth handles the process of granting that access and obtaining a token. The storage service might issue a JWT containing the allowed access and expiry time.

Using JWTs alone would still leave you to design how permission is granted and tokens are issued. Conversely, using OAuth does not require JWTs.
