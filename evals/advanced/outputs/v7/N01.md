Dependency injection means **an object receives the other objects it needs, instead of creating them itself**. Those needed objects are its *dependencies*.

Suppose an `OrderService` needs an `EmailSender`. Instead of writing `new EmailSender()` inside `OrderService`, you give it a sender through its constructor:

```java
class OrderService {
    private final EmailSender emails;

    OrderService(EmailSender emails) {
        this.emails = emails;
    }
}
```

Some other part of the application creates and connects the objects:

```java
EmailSender sender = new EmailSender();
OrderService orders = new OrderService(sender);
```

That is already dependency injection in ordinary Java. “Injection” is the act of supplying `sender` to the constructor; nothing special happens to Java itself.

**Spring can automate that setup.** When you configure Spring to manage these objects, it can create the sender and pass it into the `OrderService` constructor.

The benefit is that `OrderService` can use its sender without deciding how to construct one. Changes to the sender's setup can happen elsewhere. If the constructor accepts an interface, you can also supply different implementations—for example, a test sender—without changing the order-handling code.
