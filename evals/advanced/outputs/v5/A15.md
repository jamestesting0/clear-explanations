**The deployed SDK uses positive integer milliseconds in `timeoutMs`; legacy `timeout` is ignored.** Resolution is per-call `timeoutMs` → constructor `timeoutMs` → `QUILL_TIMEOUT_MS` → 1500 ms default, with nullish call/constructor values skipped. [A15-MIGRATION] [A15-IMPLEMENTATION]

| Request | Client wait timer | Transmitted `x-deadline-ms` | Server computation budget |
| --- | ---: | ---: | ---: |
| R1 | 6000 ms | `6000` | 5000 ms |
| R2 | 2500 ms | `2500` | 2500 ms |
| R3 | No valid timer; validation fails | Not sent | No request reaches server |

R1's call value overrides the constructor and environment. R2's `{timeout:1}` is ignored, so constructor `timeoutMs:2500` wins. R3 has no applicable `timeoutMs`; `Number("2s")` produces `NaN`, which fails validation before network activity. The SDK neither parses that duration string nor falls back to the default after this invalid value. [A15-REQUESTS] [A15-MIGRATION] [A15-IMPLEMENTATION]

The server applies `min(header,5000)`. Its 1000 ms default is irrelevant to R1 and R2 because their headers are present. [A15-SERVER]
