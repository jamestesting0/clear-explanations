## Concrete remediation

1. **Enable and verify audience enforcement now.** Set `audienceRequired=true` and ensure the verifier requires the audience array to contain the exact value `inventory-api`. Verify the expected audience configuration and array-membership behavior; requiring merely a nonempty claim would not satisfy the contract.
2. **Remove grace and enforce the strict expiration boundary.** Set the leeway to zero, but also change or supplement the comparison so it requires `now < exp`. Under the supplied implementation, zero leeway alone leaves `now <= exp`, incorrectly accepting a token at the exact instant of expiration. If build 2.6 has no supported strict-comparison option, a verifier change or additional enforcement is required; the packet does not establish that such an option already exists.
3. **Preserve the exact read-scope check.** Continue requiring `inventory:read` on this route. A write-only token must remain denied; a token containing both scopes may pass if its other claims satisfy policy.
4. **Verify the deployed trust boundary.** If the backend relies on the gateway, that design assumes every request reaching this route has passed the intended verifier, and the identity and claims forwarded to the backend cannot be substituted by the caller. Verify that trusted path and the active configuration on every serving instance. Alternatively, have the backend independently verify the signature, issuer, audience, strict expiration, and scope before accepting the route. The packet does not establish a direct-backend bypass; checking the trust assumption is different from claiming one exists.

These changes target the exact revision-7 conditions and the documented gaps. [A29-POLICY7, A29-DEPLOYMENT]
