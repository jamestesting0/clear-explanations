**Dependency injection means giving an object the other objects it needs, instead of having it create them itself.** A “dependency” is simply something the object relies on to do its work.

Suppose you already have an `EmailSender` class, and `OrderService` needs one. You can pass the sender into the constructor:

```java
class OrderService {
    private final EmailSender sender;

    OrderService(EmailSender sender) {
        this.sender = sender;
    }
}
```

Elsewhere, your setup code supplies it:

```java
EmailSender sender = new EmailSender();
OrderService orders = new OrderService(sender);
```

That is dependency injection already—just ordinary Java. The key is that `OrderService` receives its sender through a parameter rather than calling `new EmailSender()` inside itself. Passing it through the constructor is called **constructor injection**.

This separates using the sender from deciding how to create and configure it. It also makes testing easier: you can supply a test version of the dependency, provided it matches the constructor’s required type.

Spring automates the setup. You configure which objects Spring should manage, and Spring creates them and supplies their dependencies. Where your setup code above calls `new OrderService(sender)`, Spring can do the equivalent work for you.
