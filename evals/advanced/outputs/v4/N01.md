Dependency injection means **giving an object the other objects it needs to do its work**. Those other objects are its *dependencies*; “injection” just means supplying them.

For example, an `OrderService` needs something that can send messages. You can supply that through its constructor:

```java
interface MessageSender {
    void send(String message);
}

class OrderService {
    private final MessageSender sender;

    OrderService(MessageSender sender) {
        this.sender = sender;
    }

    void placeOrder() {
        sender.send("Order placed");
    }
}
```

Elsewhere, your application creates and connects the objects:

```java
// EmailSender is a class implementing MessageSender.
MessageSender sender = new EmailSender();
OrderService orders = new OrderService(sender);
```

That constructor call is dependency injection. `OrderService` says what it needs, and the code constructing it chooses what to supply. Without injection, `OrderService` might create an `EmailSender` itself using `new` inside the class.

Why bother? You can change the supplied implementation without changing `OrderService`. A test could supply a fake `MessageSender` that records messages, so testing an order doesn't send real email.

Spring automates the creation and connection of the application objects you configure it to manage. Those managed objects are called **beans**. The underlying idea is the ordinary Java constructor call shown above; dependency injection also works without Spring.
